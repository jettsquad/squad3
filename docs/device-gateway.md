# 云端设备授权

Squad 首次启动时自动生成设备密钥并建立预配置的「云端 MiniMax」连接，同时在 Agent 库创建同名 Agent。服务器从首次受理时开始发放 10 天试用。无需注册或输入账号。同一密钥重复连接沿用原期限，开通失败可在连接页重试。

在「连接」选择一个月或一年并点击「申请订阅」。授权到期后也可以申请。待审核申请不改变到期时间。后台「订阅待审核」可以批准或拒绝，批准后从原到期时间或批准时间中较晚的一个起延长一个或十二个自然月。月末按目标月份最后一天处理。App 可刷新查看审核结果与剩余期限。

将预配置 Agent 添加到团队后，在团队设置里选择当前工作站的项目目录。

管理员可以为单个设备重设期限、续期、暂停、恢复或撤销。重设期限从操作时起算，续期从现有到期日或当前时间中较晚的一天起算。填 0 表示长期。

## 后台入口

安装后后台只监听服务器的 `127.0.0.1:18226`。用自己的服务器维护身份建立 SSH 转发：

```sh
ssh -N -L 127.0.0.1:18226:127.0.0.1:18226 <维护身份>@<服务器>
```

在浏览器访问 `http://127.0.0.1:18226/`。后台登录名是 `admin`，初始随机密码保存在服务器 `/var/lib/squad-gateway/admin-password`，由管理员在自己的服务器终端读取。后台端口不开放公网。

## 部署与边界

将 `tools/device-gateway.py` 和 `tools/install-device-gateway.sh` 放在 Ubuntu 服务器的同一个目录，以 root 执行 `sh install-device-gateway.sh <客户端能访问的主机名或IPv4> [公网入口端口]`。安装要求已部署 MiniMax Codex 包装程序，以及服务器 Ed25519 SSH 主机密钥。默认公网入口为 TCP `18443`，同时承载 HTTPS 开通和设备 SSH，安全组只需一次放通该端口。设备 SSH 由仅监听 `127.0.0.1:18227` 的受限实例处理，只接受 `squad-gateway` 用户。管理员 SSH 继续走原来的 `22`。

构建客户端时，通过环境变量 `SQUAD_DEVICE_GATEWAY` 指定 `主机:入口端口:证书的64位小写SHA-256指纹`。地址和证书指纹会随应用分发。试用绑定本机设备公钥，换网无需重开。没有注册时无法识别主动生成新密钥的同一硬件，服务端对新增申请限制频率和总量。旧版账号授权继续受原账号状态约束。

设备密钥使用独立的受限 SSH 用户，每条公钥强制绑定管理入口。入口提供 MiniMax 会话、额度、授权状态和订阅申请。会话只接受 Squad 所需的 app-server 请求，每次 SSH 只运行一轮，续接绑定设备。暂停、到期和撤销拒绝新轮次；正在运行的轮次可完成，管理员撤销时可要求中断，本地结果不明确时按 Squad 的云端执行核对流程处理。

已有使用统一端口的受管连接沿用原授权。旧式手工 root 连接不受后台控制，应迁移席位并确认可独立维护服务器后，再收回其专用公钥。
